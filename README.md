# 🏗️ Design Patterns

Design Patterns são soluções reutilizáveis para problemas comuns no desenvolvimento de software. Eles ajudam a criar código mais flexível, reutilizável e fácil de manter, seguindo boas práticas de programação orientada a objetos.

## 📌 Tipos de Design Patterns

### 1️⃣ **Criacionais** 🏗️

Padrões que lidam com a criação de objetos, tornando-a mais flexível e reutilizável.

- **Factory Method** – Cria objetos sem expor a lógica de criação.
- **Abstract Factory** – Cria famílias de objetos relacionados sem depender de suas classes concretas.
- **Singleton** – Garante que uma classe tenha apenas uma instância global.
- **Builder** – Facilita a construção de objetos complexos passo a passo.
- **Prototype** – Permite a clonagem de objetos para evitar criação do zero.

### 2️⃣ **Estruturais** 🏛️

Padrões que organizam a estrutura dos objetos e classes para maior eficiência e flexibilidade.

- **Adapter** – Converte a interface de uma classe em outra esperada pelo cliente.
- **Bridge** – Separa abstração da implementação, permitindo evolução independente.
- **Composite** – Organiza objetos em estruturas hierárquicas (como árvores).
- **Decorator** – Adiciona funcionalidades a objetos dinamicamente.
- **Facade** – Simplifica a interação com subsistemas complexos.
- **Flyweight** – Otimiza o uso de memória compartilhando objetos semelhantes.
- **Proxy** – Controla o acesso a um objeto, podendo adicionar camadas extras de lógica.

### 3️⃣ **Comportamentais** 🎭

Padrões que definem como os objetos interagem entre si.

- **Chain of Responsibility** – Passa uma solicitação por uma cadeia de manipuladores.
- **Command** – Encapsula uma solicitação como um objeto.
- **Interpreter** – Define uma gramática e um interpretador para sentenças dessa gramática.
- **Iterator** – Fornece uma maneira de acessar elementos de uma coleção sem expor sua estrutura.
- **Mediator** – Facilita a comunicação entre objetos desacoplados.
- **Memento** – Permite salvar e restaurar estados anteriores de um objeto.
- **Observer** – Define uma dependência "um-para-muitos", onde mudanças em um objeto notificam outros automaticamente.
- **State** – Permite que um objeto altere seu comportamento conforme seu estado interno muda.
- **Strategy** – Define uma família de algoritmos intercambiáveis dinamicamente.
- **Template Method** – Define a estrutura de um algoritmo e permite que subclasses implementem partes específicas.
- **Visitor** – Permite adicionar operações a objetos sem modificar suas classes.

## 🎯 Por que usar Design Patterns?

✅ Melhor organização do código

✅ Maior reutilização de código

✅ Facilidade de manutenção e evolução

✅ Código mais flexível e desacoplado
